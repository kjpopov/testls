# AGENTS.md

Ground rules for anyone changing `testls`, human or AI agent. Read
[CONTRIBUTING.md](CONTRIBUTING.md) for the general process and
[docs/PLAN.md](docs/PLAN.md) for the roadmap and decision log.

## Workspace layout

| Crate | Purpose |
| --- | --- |
| `crates/testls-wire` | Hand-written TLS/SSL record and handshake codec |
| `crates/testls-data` | IANA tables, generated by `scripts/gen-iana.py` into `src/generated.rs` (do not edit by hand) |
| `crates/testls-probe` | Network probes: protocol detection, cipher enumeration |
| `crates/testls-checks` | Turns probe results into `Finding`s with a `Severity` |
| `crates/testls-report` | Output formatting (text, JSON) |
| `crates/testls-scan` | Scan pipeline shared by CLI and server; emits section events |
| `crates/testls-server` | HTTP service behind `testls serve`: REST, SSE, scan history |
| `crates/testls` | CLI binary |
| `tests/servers` | Container images for integration tests |

## Before you push

CI runs with `RUSTFLAGS=-D warnings`, so every warning fails the build.
Run locally:

```sh
scripts/gen-ocsp-fixtures.sh    # OCSP test fixtures (needs OpenSSL 3+)
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo +1.97 check --workspace   # MSRV
cargo deny check                # advisories, bans, licences, sources
                                # (cargo install --locked cargo-deny)
zizmor .github                  # if you changed workflows
```

Scanner changes must also pass the integration tests (podman or docker):

```sh
podman compose -f tests/servers/compose.yaml up -d --build
cargo test -p testls --test servers -- --ignored
podman compose -f tests/servers/compose.yaml down
```

To see coverage locally, run `cargo llvm-cov --workspace -- --include-ignored`
while the servers are up (CI publishes the same report in the job summary and on Codecov;
it runs `cargo llvm-cov nextest` so Codecov Test Analytics gets a JUnit report).
Parser changes in `testls-wire` should also survive a short fuzz run; see
[fuzz/README.md](fuzz/README.md).

## Code requirements

- **Edition 2024, MSRV 1.97.** Don't use newer features without bumping the
  MSRV in `Cargo.toml` and CI.
- **Lints:** `unsafe_code` is forbidden; clippy `all` + `pedantic` and
  `missing_debug_implementations` are enabled workspace-wide. Fix lints rather
  than silencing them; if an `#[allow]` is unavoidable, scope it narrowly and
  add a comment saying why.
- **Doc comments are required.** CodeRabbit reviews every PR and enforces
  80% doc coverage on the functions a diff touches. Give each new or changed
  `fn`, `struct`, `enum`, and `trait` a `///` comment, including private
  helpers and test functions. Each crate's `lib.rs` and each module starts with
  a `//!` summary.
- **Tests:** behavior changes need tests. Use unit tests next to the code for
  logic and `crates/testls/tests/` for end-to-end CLI behavior. Tests that
  need the local servers must be `#[ignore = "needs tests/servers running"]`.
- **Dependencies:** keep them minimal. Add shared ones to
  `[workspace.dependencies]`, and don't shell out to external tools. New
  crates must pass `cargo deny check` (see `deny.toml`); extend the licence
  allow-list only for permissive licences, with a comment naming the crate.
- **Exit codes** are part of the CLI contract: `0` = no findings at or above
  `--fail-on`, `1` = findings at or above it, `2` = scan error.

## Clean-room rule

`testls` is MIT/Apache-2.0; `testssl.sh` is GPLv2. Never copy code, cipher
tables, client-simulation data, or wording from `testssl.sh`. Derive protocol
data from IANA registries and RFCs, and cite the source in a comment.

## Branches and pull requests

- One topic per branch, based on an up-to-date `main`. Use prefixes like
  `feat/`, `fix/`, `test/`, `docs/`, `chore/`, `ci/`.
- Keep PRs small enough to review in one sitting. Split larger work into a
  series of PRs.
- Commit subjects are short and imperative, optionally prefixed with the
  area: `checks: add severity model`, `cli: report findings`.
- Update `docs/PLAN.md` when you finish a roadmap item or make a design
  decision (add it to the decision log).
- A PR is ready to merge when CI is green and the CodeRabbit comments are
  resolved.

## Notes for AI agents

- Follow everything above; AI-written changes get the same human review.
- After this file, read [docs/HANDOFF.md](docs/HANDOFF.md) (state left by
  the last session) and update it before a session ends.
- Be extremly concise. Sacrifice grammar for the sake of being concise and
  concision.
- Don't call GitHub APIs or change repository settings. Push branches and let
  the maintainer handle PRs and CI, unless the maintainer allows the `gh`
  CLI for the session; then follow [docs/agent-workflow.md](docs/agent-workflow.md).
- Assume podman, not docker, on developer machines (`podman compose ...`).
  CI uses docker.
- macOS has no `timeout` command; use tool-level timeouts instead.
